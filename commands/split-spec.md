# split-spec

1. Split the SPEC into ordered, bounded units. Each unit is behaviorally meaningful: a coherent, independently implementable and verifiable outcome, not merely a set of files or one architectural layer; preserves acceptance criteria, non-goals, security constraints, data constraints, and product scope without silent change; has a clear validation condition; and fits one fresh implementation context.
2. Prefer vertical slices where appropriate: narrow but complete behavior across the layers it needs, independently demonstrable. Do not decompose by horizontal layer only, and do not require every layer to appear in every slice.
3. State explicit dependencies per unit: what it delivers, what (if anything) it genuinely cannot begin until, and how completion is validated. Dependencies are ordering constraints only.
4. Preserve sequential execution: `/implement-spec` implements exactly one unit per invocation. No frontier execution, automatic traversal of ready units, parallel/concurrent implementers, worktree-per-unit orchestration, automatic continuation, or multi-unit execution.
5. Wide-refactor exception only: when a mechanical change has broad blast radius and vertical slices are invalid, use expand → migrate in bounded batches by meaningful blast-radius seam (package, subsystem, directory, or other repo-specific seam) → contract. Each migration batch must be independently verifiable. Keep the old form available until migration is complete when feasible; contract/removal only after all required migration batches are complete and validated. This decomposition does not authorize automatic migration execution; preserve sequential execution semantics (each expand/migrate-batch/contract step is its own unit, implemented one per /implement-spec invocation).
6. Describe outcomes, dependencies, preserved constraints, and validation; do not dictate implementation details unless the authoritative SPEC requires them; do not invent or reinterpret unresolved product decisions. If the SPEC exposes unresolved contradictions or missing decisions, report it is not ready to split safely.

Do not edit files or begin implementation.
